# 交接文档

写给接手这个项目的下一个人（或下一个 AI）。

目标：**用零依赖的 TypeScript + WebGL2 复刻 Minecraft Java Edition 1.0.0，
达到其特性面的 80% 以上**。

读完这份文档你应该能回答三个问题：现在做到哪了、代码为什么长这样、
接着该干什么。**动手之前请先读 `docs/RULES.md`** —— 那里的每一条都是
被具体的 bug 换来的。

## 一、五分钟上手

```bash
# 1. 恢复工具链（不联网，纯本机文件复制，约 34 MB）
node tools/vendor.mjs

# 2. 起开发服务器，浏览器打开 http://127.0.0.1:8080
node tools/dev-server.mjs

# 3. 全套验收（12 步，约 14 分钟）
node tools/ci.mjs
```

没有 `npm install`。**这个项目零 npm 依赖**，TypeScript 与 esbuild 是从本机
其他项目复制过来的（`tools/vendor/`、`tools/bin/`，两者都在 .gitignore 里）。
`tools/vendor.mjs` 负责重建它们；源路径写在那个脚本里，换机器要改。

> 为什么零依赖：这台机器上 npm registry **直连全部超时**，只有经本地代理
> `127.0.0.1:7897` 才通。依赖联网 = 给长跑埋随时断的雷。详见 `docs/DESIGN.md`。

## 三、闸门②：查到了三个真错，现在全绿

**结论：修的是三个不同层面的问题 —— 一个游戏 bug、一个诊断 bug、
三个验收脚本自己的 bug。**

### 一个真的游戏 bug：站在岩浆池底上不掉血

`tickVitals` 判"在不在岩浆里"只看 `floor(player.y)` 那一格。而岩浆的
`collisionShape` 是空的（人不会浮在池面上），玩家会沉到池底、被底下的
实心方块托住 —— 这时 y 是 `11.9999996`，`floor` 得到 **11**，
也就是**池底那块石头**。于是"在岩浆里"判定为假，人整个泡在岩浆里
却不再掉血。

MC 的判据是**碰撞盒与流体相交**。现在按身高扫一遍所占的格子
（`player-vitals.ts` 的 `bodyHas`），语义相同而代价只有两三次查表。
火与"站在水里灭火"同理改了。

### 一个诊断 bug：`pos` 报的东西与判定看的不是一回事

`pos` 原来只打 `feet=`（`floor(y)` 那一格），而伤害判定看的是整个身体。
两者对不上的时候，失败信息会**指向错的方向** —— 报出来是
"人没能站在岩浆里"，而人明明在里面。现在多打一个 `body=`，
就是判定实际扫的那一串格子。

诊断信息与被诊断的判定必须看同一份数据。这一条卡了很久。

### 三个验收脚本自己的错

1. **泡岩浆的时长按帧算**。4fps 的容器里 70 帧 = 17 秒 = 34 次岩浆伤害，
   人必死，于是"活着回来"那一条必然连带失败。改成按**服务端刻**算 ——
   注意不是客户端物理刻：后者被 `clock.dt` 的 0.1 秒上限截断，慢机器上
   一帧最多补 2 刻，而伤害是服务端算的（同一个坑在"按住 W 走多快"
   那一项上也犯过）。
2. **正则的反斜杠被模板字符串吃掉**。整段代码在一个模板字符串里，
   `\S` 里的反斜杠被吃掉，浏览器拿到的是 `/body=(S+)/`，匹配不到任何东西。
   （文件头上"注释里不能出现反引号"是同一类坑。）
3. **开着自然刷怪**。Y=12 的黑暗矿洞里随时刷僵尸，玩家一路被打到残血，
   于是"泡岩浆掉了多少血"量到的是"死在半路"。这一项验的是光照、
   矿物分布、工具分级、岩浆致命、活着回来 —— 名单里没有战斗，
   熬过怪是闸门①的事。

### 之前修过的两处（场景）

- **岩浆池底要垫实心方块**。`fillbox air` 只清了 `deepY..deepY+3`，
  而 `deepY-1` 是原始地形 —— Y=12 这个深度洞穴很多，池底一旦是空的，
  人就直接穿过去落到几十格以下。
- **四周要围墙**。只垫底不围边的话，九个岩浆源会朝刚清出来的空地漫过去，
  流体模拟一直有活干，`waitForIdle` 永远等不到世界安静。

## 四、代码为什么长这样

三份文档比代码更值得先读：

| 文档 | 内容 |
|---|---|
| `docs/RULES.md` | **17 条编码规约**，前 7 条由 CI 强制。每一条都写了"为什么" |
| `docs/DESIGN.md` | 架构决策：内置服务器模型、分层、顶点格式、Worker 拓扑 |
| `docs/DEVIATIONS.md` | **有意偏离 MC 的地方**，写成决策而不是 bug |
| `docs/ROADMAP.md` | 900+ 行，每个里程碑的完成记录与**踩过的坑** |

### 最要紧的五条

1. **内置服务器模型**。模拟是权威的，与渲染完全隔离。
   单人 = 服务端跑在 Web Worker 里走 MessagePort；多人 = 同一份服务端
   跑在 Node 里走 WebSocket。`ServerCore` **不含任何 Worker/DOM 依赖**，
   所以 `node --test` 能直接 `new ServerCore()` 跑几万刻做断言 ——
   这是 610 个单元测试里绝大多数的地基

2. **分层由 lint 强制**（`tools/lint-layers.mjs`）：
   ```
   core     不 import 任何人
   content  只 import core
   server   永不 import client
   client   永不 import server
   ```

3. **热循环只读扁平表**。方块是 `content/` 里的数据记录，冻结时烘焙成
   typed array。mesher、光照、碰撞、随机刻**只读那些数组，永不读对象**

4. **渲染代码禁止读挂钟**（lint 强制）。所有动画相位来自 `clock.renderTick`，
   `freeze()` 一停画面就完全静止 —— 截图回归靠这条成立

5. **文件规模**：软上限 400 行、硬上限 600 行。这条逼出了十几次拆分，
   每次都要求按"什么东西聚在一起"切，不按行数切

### 这个项目最反复出现的一类 bug

**"它让画面永远不静止"** —— 撞过四次，每次都是新加的系统让截图回归
莫名其妙地飘：

| 系统 | 开关 |
|---|---|
| 存档 | `?persist=0` |
| 野生生物 | `?mobs=0` |
| 随机刻（草蔓延、作物生长） | `?randomTicks=0` |
| 环境粒子（火把冒烟、岩浆冒泡） | `?particles=0` |

**加任何"世界会自己变"的东西时，先想好它的开关。**
验证方式是让哈希**回到原值**，不是让它"看起来对" ——
加粒子那次，关掉之后 `night-glowstone` 回到了 `5fcbd144`，
一字不差是加粒子之前的黄金值。那是证据。

### 第二反复的一类：**测试自己错了**

至少十几次，症状全都是"报出来像被测代码坏了"。几个典型：

- 黄金截图的位置基准取自**当前相机**，而相机停在哪取决于上一项检查干了什么
  → 黄金值实际绑死在检查的**顺序**上，插一项新检查后面全变
- 方块陈列阵一直在**暴雨里**拍 —— 天气是全局状态，前一批截图最后一张是 thunder
- 裂纹检查的采样频率由**网络延迟**决定（循环里夹了一次服务端往返）
- `client.last('S_BlockUpdate')` 取最后一条，而随机刻每刻都在改别处的方块
- 小屋顶不产生黑暗（踩了两次）—— 5×5 的顶，天光从四边斜着渗进来

**先怀疑测试，再怀疑代码。** 但两边都要拿证据说话。

### 三处"欠着的债"（不影响分，但会咬人）

1. **物品栏同步只带附魔摘要**（每格四个 int32 的第四个）。
   一件附了三条魔的剑，客户端只知道第一条，提示框也只显示第一条。
   给附魔单开一个包就能解决。
2. **要塞墙上的斑驳块用圆石顶替**石砖的元数据变体。它与
   "草方块侧面不跟群系染色"在等同一个改动（每面多一层 / 按 meta 取层）。
3. **掉在地上的附魔物品不发光**：`S_SpawnItems` 每项只有
   `itemId/count/damage`，协议里根本没带附魔信息。与第 1 条是同一个改动。

前两条写在 `docs/DEVIATIONS.md` 里。

### 一条方法论（这一轮最值钱的收获）

这一轮修的三十多处缺陷里，绝大多数是**同一个形状**：

> 新特性接进了一部分既有路径，剩下的静默丢弃。不报错，测试全绿，
> 只有玩家会发现东西没了。

`copyStack` 少搬一个字段、region 键少一段前缀、`saveNow` 多一句 `break`、
`enchantLevel` 一个调用者都没有 —— 每一处单看都不像 bug。

所以以后加**任何新的可选字段或新子系统**，动手前先问两句：
1. 这个字段会经过哪些搬运路径？（`grep` 一遍所有读写它的地方）
2. 有没有一条测试断言"接上了"，而不只是"算得对"？

`tests/server/enchant-gameplay.test.ts` 与
`tests/server/dimension-isolation.test.ts` 就是为这两个问题写的，

## 六、几条务必遵守的纪律

这些不是建议，是被事故换来的：

1. **不下载任何东西**。确实需要新包就单独停下来问，不要夹在多步计划里
2. **中文路径**（`D:\其他\我的世界`）：调子进程一律 `shell: false`，
   绝不经 `cmd.exe` 转发。改含非 ASCII 的文件用 Edit/Write 工具，
   **不要用 PowerShell 文本管道** —— 本机 PS 5.1 会把 UTF-8 中文打成 GBK 乱码
3. **诊断失败时先把实际错误信息读出来并原样引用**，再谈成因
4. **自动改代码的循环，终止条件必须是"编译器完全没话说"**，
   不是"我关心的那类报错没有了"。M13 有一次脚本自检说"干净"，
   实际把五个多行 const 的声明行删了、留下孤儿函数体，文件根本编译不过 ——
   因为它的过滤器只看 `TS6133|TS6192`，自己制造的 `TS1005` 全在盲区里
5. **一个 flaky 的测试比没有测试更糟**，它训练人忽略红色
6. **MC 有的常数就照抄**，自己估的数都是将来的 bug。
   已经被这条坑过三次：骷髅射箭的 `-1.1` 瞄准偏移、爆炸的两个常数、
   云的夜间亮度
7. 提交前跑 `node tools/ci.mjs`，12 步全绿再提交

## 七、已知的环境坑

| 坑 | 表现 | 对策 |
|---|---|---|
| npm registry 直连超时 | fetch failed | 经 `127.0.0.1:7897` 代理，或干脆别联网 |
| PowerShell 5.1 文本管道 | 中文变乱码 | 用 Edit/Write 工具 |
| Chrome 调试端口占用 | `端口 9333 在 20000ms 内没就绪` | 别并行跑多个浏览器检查 |
| CI 期间改源码 | 莫名其妙的失败 | 别在 CI 跑的时候编辑文件 |
| 无 GPU 的容器（SwiftShader） | 约 4fps；换维度会顶穿指令超时；`waitForIdle` 等不到安定 | 帧率类验收要在真显卡上做。冒烟里维度那三项会判成"跳过"并说明理由 |
| 多个标签页同时启动 | 互相饿死，指令全部超时 | 一个一个开（`tools/mp-check.mjs` 里就是这么做的） |
| `/tmp` 在 Windows 上 | 解析成 `D:\tmp` | 用绝对路径 |
