# 交接文档

写给接手这个项目的下一个人（或下一个 AI）。

目标：**用零依赖的 TypeScript + WebGL2 复刻 Minecraft Java Edition 1.0.0，
达到其特性面的 80% 以上**。

读完这份文档你应该能回答三个问题：现在做到哪了、代码为什么长这样、
接着该干什么。**动手之前请先读 `docs/RULES.md`** —— 那里的每一条都是
被具体的 bug 换来的。

---

## 一、五分钟上手

```bash
# 1. 恢复工具链（不联网，纯本机文件复制，约 34 MB）
node tools/vendor.mjs

# 2. 起开发服务器，浏览器打开 http://127.0.0.1:8080
node tools/dev-server.mjs

# 3. 全套验收（9 步，约 7 分钟）
node tools/ci.mjs
```

没有 `npm install`。**这个项目零 npm 依赖**，TypeScript 与 esbuild 是从本机
其他项目复制过来的（`tools/vendor/`、`tools/bin/`，两者都在 .gitignore 里）。
`tools/vendor.mjs` 负责重建它们；源路径写在那个脚本里，换机器要改。

> 为什么零依赖：这台机器上 npm registry **直连全部超时**，只有经本地代理
> `127.0.0.1:7897` 才通。依赖联网 = 给长跑埋随时断的雷。详见 `docs/DESIGN.md`。

### 常用命令

| 命令 | 作用 | 耗时 |
|---|---|---|
| `node tools/ci.mjs` | 全套 9 步 | ~7 min |

## 三、未解决问题：岩浆伤害判定

`tools/mine-check.mjs` 的第 6 项。**这是目前唯一已知未解决的问题。**

### 现象

把玩家传送进一池岩浆里泡 70 帧（约一秒多），期望掉 8 点以上血
（MC 1.0 是每 10 刻 4 点），实际掉 0 / 2 / 4 点，**每次跑都不一样**。

### 已经查明的事实（都是实测，不是推断）

```
岩浆池刚放好: -1,6=lava -1,7=lava -1,8=lava 0,6=lava 0,7=lava 0,8=lava
              1,6=lava  1,7=lava  1,8=lava
泡完之后:     （同上，九格全是 lava）
FAIL 只掉了 0 点血（20 -> 20）
  客户端 {"x":1.5,"y":12,"z":8,"onGround":true,"mode":"physics"}
  服务端 1.50,12.000000,8.00 feet=stone head=air hp=20 fire=0
```

关键矛盾：**同一个服务端、同一组坐标、相差一次往返**，
`getblock` 说 `lava`，而 `pos` 说 `feet=stone`。

已排除的可能：
- ~~玩家位置不对~~ —— 两端都是 `1.50, 12.000000, 8.00`，y 打了 6 位小数
  确认不是 `11.999999` 被 `toFixed(2)` 显示成 `12.00`
- ~~`tp` 没生效~~ —— 加了 `attachPlayer` 配对之后位置是对的
  （`tp` 是服务端的、`attachPlayer` 是客户端的，**两个都要做**，
  否则客户端按旧位置预测，下一个位置包把玩家推回去）
- ~~岩浆池没放上~~ —— 前后两次读都是九格全 lava
- ~~`stateId` 取法不同~~ —— `getblock` 与 `pos` 都是 `state & 0xfff`
- ~~常数写错~~ —— `DAMAGE_LAVA = { interval: 10, amount: 4 }`，与 1.0 一致
- ~~判定逻辑写错~~ —— `player-vitals.ts:181` 的 `feetId === 10 || feetId === 11`
  同时覆盖流动与静止岩浆；M12 的岩浆单元测试是过的

### 三条还没验证的怀疑

1. **水流过去把岩浆变成石头了**。第一版把水洼摆在离岩浆两格的地方，
   确实发生过（那是**正确**的游戏行为，是场景摆错了）。现在水挪到了
   12 格外，理论上够不着（水平流 7 格、岩浆 3 格），但没有实测确认
2. **岩浆源被自己的流动消耗掉了**。`fillbox ... lava` 放的是源块，
   而 `onBlockChanged` 会给它排计划刻。流动过程中源块的 id/meta 变化
   值得逐刻打出来看
3. **伤害真的发生了但被别的机制吃掉**。`hp=20 fire=0` 里 `fireTicks=0`
   很可疑 —— 踩进岩浆应该把 `fireTicks` 拉到 300

### 建议的下一步

按顺序做，每一步都是**先量再改**：

1. 在 `tickVitals` 里临时加一行日志，把每刻的 `feetId` 原始数值
   （不是名字）打出来，跑 70 刻看它是什么、变不变
2. 用 `pos` 的输出对照 `orescan`，确认服务端世界里那一格到底是什么
3. 如果 `feetId` 确实一直是 lava 的 id，那问题在 `v.due()` 的节流上，
   去看 `PlayerVitals.due` 的实现

**不要**在没看到 `feetId` 实际数值之前改任何判定代码 ——
这条是项目的硬规约（`docs/RULES.md` 第 16 条：验收看证据，不看声明）。

## 四、代码为什么长这样

三份文档比代码更值得先读：

| 文档 | 内容 |
|---|---|
| `docs/RULES.md` | **17 条编码规约**，前 7 条由 CI 强制。每一条都写了"为什么" |
| `docs/DESIGN.md` | 架构决策：内置服务器模型、分层、顶点格式、Worker 拓扑 |
| `docs/DEVIATIONS.md` | **有意偏离 MC 的地方**，写成决策而不是 bug |
| `docs/ROADMAP.md` | 900+ 行，每个里程碑的完成记录与**踩过的坑** |

### 最要紧的五条

1. **内置服务器模型**。模拟是权威的，与渲染完全隔离。
   单人 = 服务端跑在 Web Worker 里走 MessagePort；多人 = 同一份服务端
   跑在 Node 里走 WebSocket。`ServerCore` **不含任何 Worker/DOM 依赖**，
   所以 `node --test` 能直接 `new ServerCore()` 跑几万刻做断言 ——
   这是 366 个单元测试里绝大多数的地基

2. **分层由 lint 强制**（`tools/lint-layers.mjs`）：
   ```
   core     不 import 任何人
   content  只 import core
   server   永不 import client
   client   永不 import server
   ```

3. **热循环只读扁平表**。方块是 `content/` 里的数据记录，冻结时烘焙成
   typed array。mesher、光照、碰撞、随机刻**只读那些数组，永不读对象**

4. **渲染代码禁止读挂钟**（lint 强制）。所有动画相位来自 `clock.renderTick`，
   `freeze()` 一停画面就完全静止 —— 截图回归靠这条成立

5. **文件规模**：软上限 400 行、硬上限 600 行。这条逼出了十几次拆分，
   每次都要求按"什么东西聚在一起"切，不按行数切

### 这个项目最反复出现的一类 bug

**"它让画面永远不静止"** —— 撞过四次，每次都是新加的系统让截图回归
莫名其妙地飘：

| 系统 | 开关 |
|---|---|
| 存档 | `?persist=0` |
| 野生生物 | `?mobs=0` |
| 随机刻（草蔓延、作物生长） | `?randomTicks=0` |
| 环境粒子（火把冒烟、岩浆冒泡） | `?particles=0` |

**加任何"世界会自己变"的东西时，先想好它的开关。**
验证方式是让哈希**回到原值**，不是让它"看起来对" ——
加粒子那次，关掉之后 `night-glowstone` 回到了 `5fcbd144`，
一字不差是加粒子之前的黄金值。那是证据。

### 第二反复的一类：**测试自己错了**

至少十几次，症状全都是"报出来像被测代码坏了"。几个典型：

- 黄金截图的位置基准取自**当前相机**，而相机停在哪取决于上一项检查干了什么
  → 黄金值实际绑死在检查的**顺序**上，插一项新检查后面全变
- 方块陈列阵一直在**暴雨里**拍 —— 天气是全局状态，前一批截图最后一张是 thunder
- 裂纹检查的采样频率由**网络延迟**决定（循环里夹了一次服务端往返）
- `client.last('S_BlockUpdate')` 取最后一条，而随机刻每刻都在改别处的方块
- 小屋顶不产生黑暗（踩了两次）—— 5×5 的顶，天光从四边斜着渗进来

**先怀疑测试，再怀疑代码。** 但两边都要拿证据说话。

## 六、几条务必遵守的纪律

这些不是建议，是被事故换来的：

1. **不下载任何东西**。确实需要新包就单独停下来问，不要夹在多步计划里
2. **中文路径**（`D:\其他\我的世界`）：调子进程一律 `shell: false`，
   绝不经 `cmd.exe` 转发。改含非 ASCII 的文件用 Edit/Write 工具，
   **不要用 PowerShell 文本管道** —— 本机 PS 5.1 会把 UTF-8 中文打成 GBK 乱码
3. **诊断失败时先把实际错误信息读出来并原样引用**，再谈成因
4. **自动改代码的循环，终止条件必须是"编译器完全没话说"**，
   不是"我关心的那类报错没有了"。M13 有一次脚本自检说"干净"，
   实际把五个多行 const 的声明行删了、留下孤儿函数体，文件根本编译不过 ——
   因为它的过滤器只看 `TS6133|TS6192`，自己制造的 `TS1005` 全在盲区里
5. **一个 flaky 的测试比没有测试更糟**，它训练人忽略红色
6. **MC 有的常数就照抄**，自己估的数都是将来的 bug。
   已经被这条坑过三次：骷髅射箭的 `-1.1` 瞄准偏移、爆炸的两个常数、
   云的夜间亮度
7. 提交前跑 `node tools/ci.mjs`，9 步全绿再提交
