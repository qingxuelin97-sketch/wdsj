# 交接文档

写给接手这个项目的下一个人（或下一个 AI）。

目标：**用零依赖的 TypeScript + WebGL2 复刻 Minecraft Java Edition 1.0.0，
达到其特性面的 80% 以上**。

读完这份文档你应该能回答三个问题：现在做到哪了、代码为什么长这样、
接着该干什么。**动手之前请先读 `docs/RULES.md`** —— 那里的每一条都是
被具体的 bug 换来的。

---

## 一、五分钟上手

```bash
# 1. 恢复工具链（不联网，纯本机文件复制，约 34 MB）
node tools/vendor.mjs

# 2. 起开发服务器，浏览器打开 http://127.0.0.1:8080
node tools/dev-server.mjs

# 3. 全套验收（9 步，约 7 分钟）
node tools/ci.mjs
```

没有 `npm install`。**这个项目零 npm 依赖**，TypeScript 与 esbuild 是从本机
其他项目复制过来的（`tools/vendor/`、`tools/bin/`，两者都在 .gitignore 里）。
`tools/vendor.mjs` 负责重建它们；源路径写在那个脚本里，换机器要改。

> 为什么零依赖：这台机器上 npm registry **直连全部超时**，只有经本地代理
> `127.0.0.1:7897` 才通。依赖联网 = 给长跑埋随时断的雷。详见 `docs/DESIGN.md`。

### 常用命令

| 命令 | 作用 | 耗时 |
|---|---|---|
| `node tools/ci.mjs` | 全套 9 步 | ~7 min |
| `node --test` | 375 个单元测试 | ~2 min |
| `node tools/smoke.mjs` | 无头 Chrome，21 张黄金截图 | ~1 min |
| `UPDATE_GOLDEN=1 node tools/smoke.mjs` | 重生成黄金哈希 | |

| `node tools/persist-check.mjs` | 闸门③ 存读 | ~1 min |
| `node tools/tile-sheet.mjs` | 贴图渲成 PNG 肉眼看，不起浏览器 | ~1 s |
| 任一 gate 加 `--head` | 有头浏览器，肉眼看 | |

## 二·五、最近这轮：材质与 UI（已完成）

计划与全部细节在 **`docs/ART-PLAN.md`**，这里只说接手时要知道的三件事。

**1. 黄金哈希需要重录一次。** 这轮动了贴图内容、图集层号与界面绘制，
21 张截图哈希全部会变，是预期内的。

```bash
UPDATE_GOLDEN=1 node tools/smoke.mjs
```

改贴图时先用 `node tools/tile-sheet.mjs <名字...>` 看 —— 一秒一轮，
不用起浏览器，每格按 2×2 平铺画所以接缝一眼可见。
它走的是 `buildAtlas`，与游戏里显示的完全一致。

⚠️ **只能在录原版黄金值的那台机器上重录。** 哈希绑死在光栅化结果上，
软渲染与真 GPU 逐像素不同。这轮是在一台只有 SwiftShader 的容器上做的，
所以**没有**重录，`tests/screenshots/hashes.json` 原样未动。

**2. 顺手挖出几个既有 bug。** 都不是这轮改坏的：

- 世界里的**雪块一直是半透明的雪花粒子图** —— `RECIPES` 里
  `...SKY_RECIPES` 展开在后面，天气粒子那张也叫 `snow`，把方块的雪盖掉了。
  粒子已改名 `snowflake`
- `gold_block` 的内嵌边框**从来没画出来过** —— 最后一句 `noiseFill`
  重填整块，把上一句画的框冲干净了
- **死亡界面上是一条空的灰带子** —— 代码注释说"点阵字模画不出汉字"，
  那句话在写它的时候是对的，后来补了完整的 5×7 ASCII 字模，
  前提不成立了但没跟着改。现在画的是 `YOU DIED` / `CLICK TO RESPAWN`
- **煤炭图标几乎看不见** —— 它走的是"粉末"原型，26 粒近黑碎点撒在
  透明底上，压在深色快捷栏里就没了。改成 `lump` 原型，
  并给所有物品图标统一加了轮廓
- `UiRenderer.text()` **每次调用都重建字模表**，F3 一屏二十来行
  等于每帧重建二十遍。改成只建一次

**2.2 材质做到了什么程度。** 三步：明暗成团（可平铺格点噪声）、
**调色板量化到 6 色**（27–59 色 → 6 色，这一步才是"像素画"与"程序化噪声"
的分水岭）、手绘结构（圆石是能一块块数出来的石头，不是重叠的团）。
水/岩浆/火加了逐帧动画。细节见 `docs/ART-PLAN.md` 与 ROADMAP 第十三、十五节。

改贴图时要记住：**量化是最后一道，任何"很淡的东西"都会被并进底色**。

**2.5 `noiseFill` 与 `speckles` 已从 `texgen.ts` 删除。**
全部配方都换成了可平铺的 `valueNoise` / `blobs`。留着旧原语只会让
下一个人顺手再用一次 —— 想加贴图的话看 `tile-recipes-terrain.ts`
的头注释，那里写了标准的三段式画法。

**3. 想要原版材质，用资源包覆盖层，别往仓库里塞素材。**

```bash
node tools/dev-server.mjs --pack "<解开的资源包目录>"
# 然后开 http://127.0.0.1:8080/?pack=/pack/
```

逐张覆盖，包里没有的退回程序化生成。素材留在你自己盘上。
往仓库提交 Mojang 的 png 是再分发，公开仓库会被 DMCA —— 这条别破。

## 三、闸门②：查到了两个真错，但还没能跑通一次

**结论先说：`player-vitals.ts` 的岩浆判定是对的，问题在 `mine-check` 的场景。**

### 已经证实的（Node 里可复现，不用浏览器）

1. **岩浆没有碰撞盒**（`content/blocks-fluid.ts`：`collisionShape: []`），
   所以一池岩浆**托不住人**。而场景里 `fillbox air` 只清了 `deepY..deepY+3`，
   **`deepY-1` 是原始地形** —— Y=12 这个深度洞穴很多，池底一旦是空的，
   人就从池子里直接穿过去落到几十格以下。

   跑 `stepBody` 一验就出来：池底有石头 → y 停在 12、脚下是岩浆、掉血；
   池底是空气 → y 一路掉到 0、脚下什么都不是、不掉血。

   这解释了原来那个"掉 0 / 2 / 4 点血、**每次跑都不一样**"的现象 ——
   取决于下落过程中蹭到几刻岩浆。

2. **只垫底不围边，岩浆会漫开**。补上池底之后立刻撞上第二个问题：
   九个岩浆源朝刚清出来的空地流，流体模拟一直有活干，
   `waitForIdle` 永远等不到世界安静 —— 报"指令超时: settled"。
   现在改成先填 5×5 石头、再把中间 3×3 换成岩浆，得到一个四面加底封死的盆。

### 已经做的

- `mine-check` 的场景改成封闭的盆；清理范围从 684 格缩到 255 格
- **加了前置断言**：泡之前先确认 `feet=lava`，不成立就直接报
  "人没能站在岩浆里"并把池子再读一遍。少了这一步，"岩浆不致命（代码错）"
  和"人不在岩浆里（场景错）"会长成一模一样的失败信息 —— 之前卡了很久就是因为这个
- `pos` 现在**同时打 floor 之后的整数**（`blk=x,y,z`）。原来只打 `y.toFixed(6)`，
  而 `toFixed` 会四舍五入：`11.9999996` 照样显示成 `12.000000`，
  判定用的 `Math.floor` 却是 11
- 指令超时改成可配（`?cmdTimeout=`），默认仍是 8 秒
- `tests/server/survival.test.ts` 加了两条回归：有底托着就掉血、没底就穿过去

### 还差什么

**在这台机器上没能跑通一次完整的 `mine-check`。** 它是个无 GPU 的容器，
软件渲染（SwiftShader）只有 6 fps，`waitForIdle` 有大约一半的概率超时 ——
与岩浆无关，第 1、2 段（挖矿、钻石）每次都过。

最后一次拿到的失败信息是：池子九格全是 lava，而 `pos` 说 `feet=stone`。
**加的 `blk=` 就是为了定这一刀**（究竟是 y 被 floor 到了 11，还是别的），
但每次跑到那一步之前就先在 `settled` 上超时了，一直没读到。

接手的人在**有 GPU 的机器上**跑一次 `node tools/mine-check.mjs` 就能看到
`blk=` 那三个数，大概率一眼定位。

## 四、代码为什么长这样

三份文档比代码更值得先读：

| 文档 | 内容 |
|---|---|
| `docs/RULES.md` | **17 条编码规约**，前 7 条由 CI 强制。每一条都写了"为什么" |
| `docs/DESIGN.md` | 架构决策：内置服务器模型、分层、顶点格式、Worker 拓扑 |
| `docs/DEVIATIONS.md` | **有意偏离 MC 的地方**，写成决策而不是 bug |
| `docs/ROADMAP.md` | 900+ 行，每个里程碑的完成记录与**踩过的坑** |

### 最要紧的五条

1. **内置服务器模型**。模拟是权威的，与渲染完全隔离。
   单人 = 服务端跑在 Web Worker 里走 MessagePort；多人 = 同一份服务端
   跑在 Node 里走 WebSocket。`ServerCore` **不含任何 Worker/DOM 依赖**，
   所以 `node --test` 能直接 `new ServerCore()` 跑几万刻做断言 ——
   这是 366 个单元测试里绝大多数的地基

2. **分层由 lint 强制**（`tools/lint-layers.mjs`）：
   ```
   core     不 import 任何人
   content  只 import core
   server   永不 import client
   client   永不 import server
   ```

3. **热循环只读扁平表**。方块是 `content/` 里的数据记录，冻结时烘焙成
   typed array。mesher、光照、碰撞、随机刻**只读那些数组，永不读对象**

4. **渲染代码禁止读挂钟**（lint 强制）。所有动画相位来自 `clock.renderTick`，
   `freeze()` 一停画面就完全静止 —— 截图回归靠这条成立

5. **文件规模**：软上限 400 行、硬上限 600 行。这条逼出了十几次拆分，
   每次都要求按"什么东西聚在一起"切，不按行数切

### 这个项目最反复出现的一类 bug

**"它让画面永远不静止"** —— 撞过四次，每次都是新加的系统让截图回归
莫名其妙地飘：

| 系统 | 开关 |
|---|---|
| 存档 | `?persist=0` |
| 野生生物 | `?mobs=0` |
| 随机刻（草蔓延、作物生长） | `?randomTicks=0` |
| 环境粒子（火把冒烟、岩浆冒泡） | `?particles=0` |

**加任何"世界会自己变"的东西时，先想好它的开关。**
验证方式是让哈希**回到原值**，不是让它"看起来对" ——
加粒子那次，关掉之后 `night-glowstone` 回到了 `5fcbd144`，
一字不差是加粒子之前的黄金值。那是证据。

### 第二反复的一类：**测试自己错了**

至少十几次，症状全都是"报出来像被测代码坏了"。几个典型：

- 黄金截图的位置基准取自**当前相机**，而相机停在哪取决于上一项检查干了什么
  → 黄金值实际绑死在检查的**顺序**上，插一项新检查后面全变
- 方块陈列阵一直在**暴雨里**拍 —— 天气是全局状态，前一批截图最后一张是 thunder
- 裂纹检查的采样频率由**网络延迟**决定（循环里夹了一次服务端往返）
- `client.last('S_BlockUpdate')` 取最后一条，而随机刻每刻都在改别处的方块
- 小屋顶不产生黑暗（踩了两次）—— 5×5 的顶，天光从四边斜着渗进来

**先怀疑测试，再怀疑代码。** 但两边都要拿证据说话。

## 六、几条务必遵守的纪律

这些不是建议，是被事故换来的：

1. **不下载任何东西**。确实需要新包就单独停下来问，不要夹在多步计划里
2. **中文路径**（`D:\其他\我的世界`）：调子进程一律 `shell: false`，
   绝不经 `cmd.exe` 转发。改含非 ASCII 的文件用 Edit/Write 工具，
   **不要用 PowerShell 文本管道** —— 本机 PS 5.1 会把 UTF-8 中文打成 GBK 乱码
3. **诊断失败时先把实际错误信息读出来并原样引用**，再谈成因
4. **自动改代码的循环，终止条件必须是"编译器完全没话说"**，
   不是"我关心的那类报错没有了"。M13 有一次脚本自检说"干净"，
   实际把五个多行 const 的声明行删了、留下孤儿函数体，文件根本编译不过 ——
   因为它的过滤器只看 `TS6133|TS6192`，自己制造的 `TS1005` 全在盲区里
5. **一个 flaky 的测试比没有测试更糟**，它训练人忽略红色
6. **MC 有的常数就照抄**，自己估的数都是将来的 bug。
   已经被这条坑过三次：骷髅射箭的 `-1.1` 瞄准偏移、爆炸的两个常数、
   云的夜间亮度
7. 提交前跑 `node tools/ci.mjs`，9 步全绿再提交
