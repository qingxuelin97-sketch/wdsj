# 美术优化计划：材质与 UI

目标：**在不引入任何第三方素材的前提下，把画面从"能看出是什么"提到"看着像那么回事"。**

写这份文档的起因：M13 之后第一次系统地看整批截图，结论是几何、光照、
昼夜、天气都已经到位，**短板集中在两处** —— 方块贴图的质感和界面的立体感。

---

## 一、素材来源：为什么还是不下载

调研过"直接下一套贴图"这条路，结论是**不走**，两个理由：

1. **版权**。README 的头号承诺是「不含任何 Mojang 素材」。Minecraft 的贴图
   是 Mojang 的专有美术资产，搬进仓库就直接推翻这条。绝大多数第三方
   资源包（Faithful 一类）本身就是 Mojang 贴图的衍生作品，同样不行。
2. **零依赖**。贴图一旦变成需要下载的二进制资产，`tools/vendor.mjs`
   那套"纯本机文件复制"的重建路径就断了，长跑期间又多一个联网的雷。

**但上网是有价值的** —— 查的是**参考值与技法**，不是文件：

| 查到的东西 | 用途 | 来源 |
|---|---|---|
| MC GUI 调色板的确切 hex | 界面配色照抄，不再自己估 | colorswall / color-hex |
| 白噪声 vs 蓝噪声/成团噪声 | 定位"糊感"的根因 | ditherpunk 等 |
| 无缝平铺：半幅偏移补缝法 | 修贴图接缝 | 通用像素画教程 |

这与 `docs/RULES.md` 第 6 条（「MC 有的常数就照抄」）是一致的：
**抄的是数值，不是文件。**

> 如果将来决定要 vendor 真素材，那必须是一次明确的、单独的决定，
> 并且只能用 CC0 / CC-BY-SA 的开放素材（如 Luanti 默认包、Kenney），
> 附带出处与许可声明。**不要夹在别的改动里顺手做掉。**

## 二、问题诊断

### 2.1 贴图：白噪声没有结构

`TilePainter.noiseFill` 是**每像素独立随机**：

```ts
const d = (this.rand() - 0.5) * 2 * variance;
this.set(x, y, c.r + d, c.g + d, c.b + d, ...);
```

这是白噪声。它在 16×16 上的观感就是电视雪花点 —— 逐像素看有变化，
退开一步看是**一片均匀的糊**，因为相邻像素毫无相关性，
在视觉上直接平均掉了。

真正的像素画靠的是**成团的色块**：几个亮斑、几个暗斑，各占三五个像素，
边界清楚。人眼读的是这些团块，不是单个像素。

### 2.2 贴图：不平铺，边上还丢像素

`speckles()` 从随机点开始画 `size × size`：

```ts
for (let y = y0; y < y0 + size; y++)
  for (let x = x0; x < x0 + size; x++) this.set(x, y, ...);
```

而 `set()` 遇到越界**直接 return**。于是靠近右边和下边的斑点被切掉一半，
左边和上边永远没有半个斑点。两块同贴图的方块并排时，接缝处一侧密一侧疏。

正确做法是**环绕**：`x % 16`，被切掉的那半从对边长回来。
这同时也让贴图真正无缝。

### 2.3 贴图：没有明暗，读不出体积

MC 的贴图普遍带一层很轻的边缘暗化 —— 靠近方块边界的一两个像素稍暗。
这让每个方块在一片同材质的墙面上仍然能被数出来。
现在的贴图完全没有，于是一面石墙就是一整块均匀的灰。

### 2.4 UI：纯色矩形，没有斜面

现在的面板：

```ts
ui.rect(px - 8, panelTop, 9 * SLOT + 16, panelH, 0.78, 0.78, 0.78, 1);
ui.rect(px - 6, panelTop + 2, ..., 0.86, 0.86, 0.86, 1);
```

两层灰。MC 的界面之所以一眼认得出，靠的是 **Windows-95 式的斜面**：
外凸的面板左上白、右下深灰；内凹的槽位反过来，左上深灰、右下白。
这一步几乎不花性能（多几个 1px 的矩形），但观感差别是"草图"和"成品"。

配色也是估的（0.78 / 0.86），而 MC 有确切值。

## 三、实施

### 阶段 A：给 TilePainter 加原语（`texgen.ts`）

| 原语 | 作用 | 解决 |
|---|---|---|
| `valueNoise(c, amp, cells, octaves)` | 可平铺的格点插值噪声 | 2.1 |
| `blobs(c, count, radius)` | 环绕的成团斑块 | 2.1 / 2.2 |
| `grain(c, amp, vertical)` | 方向性纹理（木纹） | 2.1 |
| `edgeShade(strength)` | 边缘暗化 | 2.3 |
| `dither(c, ratio)` | 有序抖动（Bayer 4×4） | 2.1 |
| `setWrapped()` | 环绕写像素 | 2.2 |

原则不变：**按贴图名字播种**，输出**完全确定**，直接写 `Uint8ClampedArray`。

### 阶段 B：重写配方（`tile-recipes.ts`）

按"在画面里出现的面积"排序，先改最赚的：

1. `stone` `cobblestone` `dirt` `grass_top` `grass_side` `sand` `gravel`
2. `planks` `log_side` `log_top` `leaves`
3. 六种矿石（MC 的矿石是**带暗边的亮团**，不是随机点）
4. 其余按需

### 阶段 C：UI（`inventory-screen.ts`）

照抄 MC 调色板：

| 用途 | 值 |
|---|---|
| 面板底 | `#C6C6C6` |
| 面板高光（左上） | `#FFFFFF` |
| 面板阴影（右下） | `#555555` |
| 外框 | `#000000` |
| 槽位底 | `#8B8B8B` |
| 槽位暗边（左上） | `#373737` |
| 槽位亮边（右下） | `#FFFFFF` |

面板外凸、槽位内凹。热键栏同理。

### 阶段 D：验证

跑 `tools/smoke.mjs`，**逐张肉眼看**改动前后。

> ⚠️ **不要在非目标机器上跑 `UPDATE_GOLDEN=1`。**
> 黄金哈希绑死在光栅化结果上，软渲染（SwiftShader）与真 GPU 逐像素不同。
> 在软渲染的机器上重录会把仓库的黄金值污染成软渲染值，
> 之后在真 GPU 上跑就永远是红的。**黄金值只在录它的那台机器上重录。**

---

### 阶段 E：资源包覆盖层（已做）

计划外加的，起因是"想要原版材质"这个需求本身合理，但**把 Mojang 的
png 提交进仓库不行** —— 那是再分发，公开仓库会被 DMCA。

做法是把这件事翻译成一个功能：`src/client/render/resource-pack.ts`
在启动时按名字覆盖程序化图集，素材由使用者自己指定、留在自己盘上。

```bash
# 把 1.0.jar 里的 assets/ 解到任意目录，然后：
node tools/dev-server.mjs --pack "D:/其他/解出来的资源包"
# 浏览器开 http://127.0.0.1:8080/?pack=/pack/
```

- 逐张覆盖，包里没有的退回程序化生成 —— 只解出十几张也能用
- 名字映射见 `pack-names.ts`：MC 自己在 1.13 那次"扁平化"重命名里
  把 `log_oak` 改成了 `oak_log`、目录从 `blocks/` 改成 `block/`，
  两套都试
- `--pack` 挂在同源的 `/pack/` 下。另起一个静态服务器会撞上本服务器
  给所有响应打的 `COEP: require-corp`
- **一律缩到 16×16**。图集是单一尺寸的 TEXTURE_2D_ARRAY，混不了。
  HD 包（32×/64×）因此等于白费 —— 要真支持得让 `TILE_SIZE` 变成
  运行时值，是独立的一件事

## 四、这轮顺手挖出来的两个 bug

都不是这次改坏的，是原本就在、被这轮改动照出来的。

### 4.1 世界里的雪块是半透明的雪花粒子图

`RECIPES` 是个对象字面量，`...SKY_RECIPES` 展开在地形那批**后面**，
同名键后者胜。天气用的雪花粒子配方正好也叫 `snow`，于是雪方块（id 80）
与雪层拿到的是那张"透明底 + 十六粒白点"的粒子图。

修法：粒子改名 `snowflake`（它内部本来就是用 `fnv1a('snowflake')` 播种的，
作者原意就是这个名字），`client-main.ts` 取层号处跟着改。

### 4.2 `gold_block` 的内嵌边框从来没画出来过

```ts
noiseFill(...); rect(1, 1, 14, 14, ...); noiseFill(...);
```

第三句重填整块，第二句画的内框一个像素都不剩。

**这一类要当心**：`valueNoise` / `noiseFill` 都是整块重填，
在它们**之后**才能画特征。

## 五、明确不做的

- 不提高贴图分辨率。16×16 是 MC 1.0 的规格，也是 `TILE` 常量的前提，
  改它会牵动图集、mipmap、mesher 的 UV
- 不加法线贴图 / PBR。1.0 没有，加了就不是复刻了
- 不动着色器的光照模型。这次只改**贴图内容**与**界面绘制**，
  不碰 `block-shader.ts` —— 那是另一件事，混在一起会让截图回归无法归因

---

## 六、给下一个人：黄金哈希要重录

这轮动了贴图内容、图集层号（`snow` 改名 `snowflake` 会挪动后面所有层号）
与界面绘制，**21 张黄金截图哈希全部会变**，这是预期内的。

```bash
UPDATE_GOLDEN=1 node tools/smoke.mjs   # 只在你自己那台机器上跑
```

⚠️ **必须在录原版黄金值的那台机器上重录。** 哈希绑死在光栅化结果上，
软渲染（SwiftShader）与真 GPU 逐像素不同 —— 在软渲染的机器上重录，
会把仓库的黄金值污染成软渲染值，之后在真 GPU 上跑永远是红的。

本轮的改动是在一台只有 SwiftShader 的 Linux 容器上做的，
所以**没有**重录，`tests/screenshots/hashes.json` 保持原样。
CI 会因此报 21 项哈希不匹配，重录一次即可。

功能性断言全部是绿的（萤石光照、粒子确定性、生物、瀑布、生存 HUD、
陈列阵 118 块、形状 26 个），新加的 `tests/client/atlas.test.ts`
六项也全绿。
