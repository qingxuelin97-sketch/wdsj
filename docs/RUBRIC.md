# 评分表

把"达到 MC 1.0 的 80%"变成一个可以逐项打分的数字。
每个子项按 0.5 分为最小单位。**只给在游戏里生存模式下能真正触发的行为算分，代码存在不算。**
任何一类若会崩溃或损坏存档，该类计 0 分。

**三项闸门测试**，任一不过总分封顶 60：
1. **第一夜** —— 出生 → 徒手打木 → 合成台+工具 → 搭掩体 → 熬过有怪的一夜
2. **下矿** —— 下到 Y<16，火把照明找到钻石，躲开岩浆，活着回来
3. **存读** —— 退出重进，世界/背包/容器内容/时间完全还原

## 分数标尺

- **60** = "一个体素游戏"：地形、挖掘、合成、一种敌对生物、昼夜、存档
- **70** = "一个类 MC 游戏"：群系、洞穴、正确矿物带、完整工具树、饥饿、5 种生物、流体、箱子、音效
- **80** = "缺了终局的 1.0 复刻"：以上加苦力怕爆坑、下界、床、农业、红石基础、平滑光照、
  环境音、天气、约 120 条配方、约 60 种方块
- **90** = 再加附魔、酿造、经验、末地与末影龙、村庄、矿车、完整红石
- **100** = 成就、统计、地图、唱片、画作、全部 110 种方块、多人

**本项目按 90+ 规划**，里程碑排序保证 M14 完成时越过 80 分线，之后继续推下界、末地、多人。
砍掉的内容见 [DEVIATIONS.md](DEVIATIONS.md)。

### 2026-08-31 的这一次打分怎么来的

**扣分的九处**，每一处都是"游戏里真的没有"，不是"代码里没写完"：

| −1 | 手持渲染 | 第一人称手里不画东西 |
| −0.5 | 水下 | 泡在水里没有蓝色滤镜与雾 |
| −1 | 难度 | 只有普通难度，不可选 |

**三项闸门**：

| 闸门 | 状态 | 依据 |
|---|---|---|
| ① 第一夜 | ✅ | `tools/first-night-check.mjs`，M12 通过 |
| ② 下矿 | ✅ | `tools/mine-check.mjs`，连跑三次全绿。查到并修掉一个**真的游戏 bug**：站在岩浆池底上时 `floor(y)` 落到池底那块石头上，人整个泡在岩浆里却不再掉血（见下） |
| ③ 存读 | ✅ | `tools/persist-check.mjs`，M9 通过 |

**闸门②沿路查出来的一个真 bug**：`tickVitals` 判"在不在岩浆里"只看
`floor(player.y)` 那一格。而玩家站在岩浆池底上时，脚下有实心方块托着，
y 会停在 `11.9999996` —— floor 得到 11，也就是**池底那块石头**，
于是判定为假，人整个泡在岩浆里却不再掉血。

MC 的判据是**碰撞盒与流体相交**。现在按身高扫一遍所占的格子
（`bodyHas`），语义相同而代价只有两三次查表。火与灭火同理。

诊断信息本身也修了：`pos` 原来只打 `feet=`（floor 那一格），
与伤害判定看的东西对不上 —— 失败信息会指向错的方向。
现在多打一个 `body=`，就是判定实际扫的那一串。

顺带修掉三处**验收脚本自己的错**（都不是游戏的问题）：
泡岩浆的时长按帧算（4fps 的容器里 70 帧 = 17 秒，必死）、
正则的反斜杠被模板字符串吃掉、以及开着自然刷怪让这一项随机失败。

**性能那三条**（M17 的验收标准之一）：服务端每刻 3.39ms（线 25ms）✅、
多人指令往返 50.5ms（线 100ms）✅、三分钟堆漂移 ×0.90 ✅；
客户端帧率与十分钟内存**都要在真显卡上补测**（容器是软件渲染，
4fps，十分钟那一档标签页会中途崩掉）。

**离 100 还差的**：成就、统计、地图、唱片、画作、村庄、矿车与船的实体、
创造模式、剩下四种生物、下界要塞那一套。都是明确的、可以逐项加的东西，
没有任何一项需要动架构。
